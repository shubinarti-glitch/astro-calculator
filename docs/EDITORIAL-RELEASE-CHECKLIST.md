# Проверка релиза после отделения контента

Не запускать прежний деплой только через git pull: без приватных файлов новый backend не должен стартовать. Не перезаписывать рабочую базу, ключи, платежные настройки или CMS overrides локальными копиями.

## Приватные входные данные

Для сайта обязательны `data/editorial/text-tables-v1.json`, `text-snippets-v1.json`, `glossary-v1.json`. Существующие authored_content/authored_transit_content/transit_en и изменения CMS сохраняются. Для сборки Android обязателен `data/editorial/android-v1.json`; на веб-сервере он сам по себе не нужен.

В `data/editorial/` есть также резервные копии и оригиналы: НЕ переносить папку целиком. Изменённые исходники и необходимые JSON должны обновляться согласованно. Сначала проверить комплект в изолированном staging, затем подготовить резервную копию кода и контент-пакета текущего production, остановку/переключение и откат по действующей схеме хостинга. Секреты и БД в пакет исходников не включать.

`backend/editorial_required.json` содержит только обязательные ключи и входит в исходники. Веб-приложение проверяет комплектность при старте. Самостоятельный smoke-check:

```powershell
.\venv\Scripts\python.exe -c "from backend.editorial_data import validate_required; validate_required(); print('Editorial package OK')"
.\venv\Scripts\python.exe scripts/content_regression_snapshot.py compare data/content_evidence/pre-extraction-extended.json --extended
.\venv\Scripts\python.exe -m pytest -q
node --test tests/test_pdf_report.mjs
```

Снимок сравнения приватный и относится к редакции до миграции. Новые намеренные редакционные изменения нужно проверять отдельно, а не молча перезаписывать baseline.

## Android

Сохранены офлайн-данные и прежние интерфейсы Kotlin. Проверять генератор, точность данных, обе магазинные сборки и доступ к Таро/лунным советам из workers без Activity. Debug-unit tests не заменяют проверки подписанного release и устройства. Production APK не заменять непроверенной сборкой.

## Публичные исходники

`build_public_source.py` пока создаёт только черновой снимок и явно сообщает о недостающих входных данных и уведомлениях. Он не подтверждает лицензионную комплектность. Не публиковать этот черновик и не заменять им автоматически существующий доступ к соответствующим исходникам. Отдельно решить правовой статус ранее опубликованных встроенных текстов, комплектность исходников и демонстрационные данные. Частный пакет не устраняет возможность извлечения уже отображённых текстов и текстов из офлайн-APK.

## Проверки после разрешённого выпуска

Проверить запуск сервиса, /api/glossary на RU/EN, натальную карту, транзиты, календарь, SEO-страницу и PDF; проверить гостевой и платный доступ, отсутствие закрытых JSON в static root. При любой потере текста или ошибке чтения пакета откатить код и контент-пакет совместно. Не выполнять новый force-push истории до завершения полного аудита удаляемого контента.
