# Защита контента и минимизация раскрытия личности

Дата: 22 сентября 2026. Это стратегия и ограниченный аудит локального кода, не отчёт о внедрённой защите. Production, CDN, DNS, все метаданные и полный APK в этой проверке не обследованы. Новые изменения на сервер не опубликованы.

## Вывод и границы

Браузер получает любой текст, который показывает. DevTools, сохранение страницы, автоматизация браузера, OCR и ручное переписывание позволяют извлечь увиденное. Перенос с HTML в API или серверный рендеринг сам по себе этого не устраняет. Цель — не отдавать весь корпус, ограничивать масштаб выгрузки и сохранять доказательства происхождения материалов.

Разделить три задачи: затруднение массового копирования; минимизация личных технических следов; доказательства создания. Ни одна из них автоматически не решает остальные.

Авторский контент нельзя автоматически объявлять свободным только из-за библиотеки AGPL. Но и перенос ранее опубликованных строк в JSON не отменяет прежних лицензий и не доказывает независимость произведений от программы. Соответствующий исходный код распространяемых версий должен оставаться комплектным. Условия на будущий независимый редакционный пакет и уже опубликованные версии рассматриваются отдельно.

## Целевая архитектура

```text
Браузер / APK
    ↓ HTTPS: конкретный отчёт или страница, а не полный корпус
CDN / WAF / Bot Protection
    ↓ проверенный клиентский IP, ограничения частоты
Reverse Proxy
    ↓
Backend: авторизация → права → квоты → расчёт → минимальный ответ
    ├── Private Content Storage: версионированный редакционный пакет
    └── Database / CMS: права доступа, редакции, аудит
```

CMS и хранилище доступны только внутреннему сервису и редакторам. Контент не находится в static root, JS-бандлах, Docker-слоях публичного образа или публичном Git. Локальные оригиналы сохраняются до любых преобразований. В открытом коде — движок загрузки и отдельно созданный нейтральный демонстрационный набор, если это совместимо с обязательствами по конкретной версии программы. Демонстрационный набор нельзя выдавать за соответствующий исходник старого релиза, если это нарушает комплектность.

APK: встроенный офлайн-контент извлекается из APK. Закрыть его от владельца устройства шифрованием с ключом в приложении нельзя. Для будущего приложения возможна серверная выдача по правам и ограниченный приватный кэш; потеря полного офлайн-доступа — отдельное продуктовое решение. Уже полученные тексты пользователь всё равно может сохранить. Расчётный движок и редакционные материалы рассматриваются раздельно; AGPL/GPL-обязательства Android сохраняются.

## HTML и SEO

Для поисковых страниц оставить публичные, осознанно выбранные материалы или самостоятельные краткие обзоры. Полные платные трактовки — после серверной проверки прав. Не помещать полный скрытый текст в DOM, data-атрибуты, inline JSON, accessibility-атрибуты или HTML-комментарии. Динамический запрос должен возвращать только выбранный материал, без соседних записей и каталога контента.

SSR полезен для скорости и индексации, но не защищает текст. Изменение полных SEO-страниц на краткие может ухудшить трафик: сначала сравнить трафик и конверсию. Не отдавать поисковику тайно полный текст, скрытый от обычного пользователя. Имена классов и ID должны отражать функцию, не ФИО, рабочие пути или внутренние редакционные заметки.

## JavaScript и сборка

Выносить именно редакционные произведения и длинные трактовки; названия кнопок и доступные подписи могут оставаться в клиенте. Frontend не хранит секреты. Выключить публикацию source maps и проверить, что они действительно возвращают 404, включая maps библиотек. Минификация — для размера и удаления необязательных комментариев, не криптографическая защита. Сохранить обязательные уведомления библиотек. Удалять debug-логи и рабочие пути из сборки. Не менять inline-скрипт темы без пересчёта CSP-хэша.

Тяжёлая обфускация осложняет поддержку и производительность, практически не защищает уже отображённый текст. AGPL-исходники не становятся закрытыми из-за минификации.

## API и сервер

Обязательно: серверная проверка прав на каждый материал; явные схемы ответов для brief/detailed; отсутствие всего корпуса и лишних вложенных полей; запрет параметрам клиента повышать права; ограничения размера тела, диапазона дат, количества результатов, параллельных задач и времени расчёта. Не считать CORS, скрытый URL или UUID авторизацией. Токен с коротким сроком привязывать к пользователю и операции; публичный токен, доступный любому клиенту, не останавливает scraping.

Лимиты: отдельные бюджеты на пользователя, сессию и IP, отдельно дорогие расчёты и текстовые страницы. Счётчики в общем хранилище для нескольких worker-процессов. Порог выбирать по измеренному нормальному трафику, сначала режим наблюдения, затем мягкое замедление/429 с Retry-After. Один IP может принадлежать многим пользователям. Не доверять произвольному X-Forwarded-For: принимать только от настроенного доверенного прокси. Закрыть прямой внешний доступ к origin после проверки схемы развёртывания.

Полезно: CDN/WAF с правилами на классы маршрутов, репутация IP, рост числа уникальных материалов, последовательный обход URL, высокая параллельность, частые ошибки токенов, обход лимитов через смену адресов. Оценивать сочетание сигналов, а не один User-Agent. Проверенным поисковым роботам — отдельные правила; одного названия Googlebot недостаточно. Challenge только при подозрениях; APK должен обрабатывать лимиты штатно, а не получать HTML-капчу вместо JSON. Предусмотреть доступный альтернативный путь пользователям без JS.

Fingerprinting: минимальные краткоживущие признаки запроса/сессии; не скрытый постоянный межсайтовый идентификатор. Honeypot-маршрут может быть слабым сигналом, но не единственным основанием блокировки: его способны открыть сканеры и средства доступности. Не портить ответы вымышленными трактовками.

Журналировать время, класс маршрута, статус, объём, длительность, псевдонимный идентификатор и срабатывание лимита. Не писать текст отчёта, Bearer-токены, полную дату/место рождения, секреты и необработанный query string. Ограничить доступ и срок хранения; конкретный срок определить по операционной необходимости. При аномалии — постепенное ограничение и сигнал оператору, затем блокировка с возможностью пересмотра.

Кэш: публичные страницы можно кэшировать; персональные отчёты не помещать в общий CDN-кэш. Если есть внутренний кэш, ключ учитывает права, язык, параметры, версию контента; предотвращать смешивание пользователей. Очистка кэша при отзыве прав. Проверять Service Worker и offline storage отдельно.

Production: отключить debug, внешние debug endpoints и ненужные docs; обобщённые 500 без traceback; request ID для внутренней диагностики; убрать лишние Server/X-Powered-By. Эти заголовки не скрывают стек полностью. CSP, nosniff, HTTPS и защита framing остаются; HSTS включать только после проверки всех нужных HTTPS-сценариев. Ошибки 404/422/500 также проверять на пути, значения ввода и персональные данные.

Избыточно: обфускация всего интерфейса, постоянные капчи, скрытие текста в canvas, агрессивные блокировки по стране или одному IP, запрет DevTools. Они ухудшают UX и не решают задачу.

## Обычное копирование

| Мера | Эффективность | Недостаток / решение |
|---|---|---|
| Запрет выделения | Очень низкая | Мешает чтению и переводу; не использовать как основную меру |
| Запрет context menu | Очень низкая | Не мешает Network/сохранению; убрать при пересмотре UX |
| Ctrl+C, copy/cut | Очень низкая | Мешает законным пользователям и помощникам; не расширять |
| Запрет drag-and-drop | Низкая | Не защищает исходник изображения или текста |
| JS anti-copy | Низкая | Отключается, обходится браузером без JS |
| Видимый watermark бренда | Сдерживает небрежное присвоение | Можно удалить/OCR; не перекрывать текст |
| Непубличный ID отчёта | Помогает расследованию при наличии журнала | Не публиковать email/ФИО клиента; не доказывает авторство сам по себе |
| Выдача по запросу и квоты | Полезна против массовой выгрузки | Не препятствует копированию уже выданного материала |

## Метаданные и личные следы

Ниже план проверок; отсутствие находок по всем строкам ещё не подтверждено.

|---|---|---|---|
| HTML comments | Имена, заметки, пути | View Source, поиск в сборке | Удалить необязательные заметки |
| JS comments | Автор, рабочие задачи | Sources и поиск | Production-минификация с сохранением лицензий |
| CSS comments | Автор, инструменты | CSS-ответы | Удалить необязательное |
| Source maps | Исходники, пути | sourceMappingURL и запрос .map | Не публиковать, хранить приватно |
| EXIF | GPS, автор, устройство | exiftool на копиях | Чистить только экспортные копии |
| PDF metadata | Author, Creator, пути | pdfinfo/exiftool | Нейтральный бренд, проверить финальный PDF |
| SVG metadata | Редактор, автор, пути | XML metadata/title/desc | Сохранить доступные описания, убрать личное |
| Изображения | Лицо, подпись | Визуальный осмотр и метаданные | Отдельные публичные версии; лицо уже раскрывает личность |
| Названия файлов | ФИО, даты, задачи | Список выдаваемых assets | Нейтральные имена; не ломать ссылки |
| URL | Имена/внутренние ID | Network, маршруты | Нейтральные стабильные slug |
| Favicon/asset paths | Бренд и происхождение | HTML/manifest | Бренд допустим; исключить личные пути |
| Package metadata | author, email, repository | Манифесты пакетов | Служебные реквизиты при наличии права их менять |
| Git history | Автор, email, прошлые материалы | Все refs и коммиты | Отдельный исходный репозиторий; историю оценивать отдельно |
| GitHub/GitLab | Username, профиль, связи | Публичный профиль | Неперсональная организация возможна; прежние следы сохраняются |
| npm | Maintainers, email | Публичный пакет | Не публиковать ненужные пакеты; проверить tarball |
| Docker images | ENV, слои, labels | inspect/history и содержимое образа | Не включать контент/секреты, build secrets вместо ARG |
| HTTP headers | Стек, upstream | curl -I, 4xx/5xx | Минимальные заголовки прокси |
| Error pages | Traceback, пути, ввод | Безопасный неверный запрос | Обобщённые сообщения, внутренний журнал |
| Sitemap | Каталог страниц | robots/sitemap | Только намеренно публичные URL |
| RSS/Atom | Полные статьи, email | Поиск feed links | Краткие выдержки; наличие feed пока не подтверждено |
| JSON-LD | Person, sameAs | HTML и rendered DOM | Organization/бренд, если соответствует действительности |
| Open Graph | Имена/изображения | og:* | Публичные брендовые сведения |
| Structured data | Автор/контакты | JSON-LD, microdata, RDFa | Согласовать с видимой страницей |
| robots.txt | Пути | GET robots.txt | Не указывать секретные пути; это просьба роботам, не контроль доступа |
| API | Личные поля, названия | Network и схемы ответов | Явный разрешённый набор полей |
| DNS/subdomains | Почта, инфраструктура | A/AAAA/MX/TXT, известные имена | Убрать устаревшее после проверки зависимостей; история DNS остаётся |
| Email | Личный контакт | HTML/JSON/документы | Ролевой адрес при необходимости; не нарушать обязательные раскрытия |
| Analytics | Связи проектов, ID | Network/config | Неиспользуемое убрать; не считать публичный ID секретом |
| Third-party scripts | Передаваемые сведения | Network, storage | Минимум поставщиков, никаких текстов отчётов и токенов |

Публичные юридические документы и карточка автора уже раскрывают личность. Не удалять реквизиты вслепую: сначала определить обязательные сведения и желаемый формат бренда. Полная анонимность несовместима с сохранением текущей публичной биографии. Лицензионные уведомления третьих лиц не удалять ради минимизации метаданных.

## Доказательства без публичного ФИО

Публичная подпись может быть брендом; связь с правообладателем хранится в частных документах. Частный репозиторий, оригиналы, черновики, история правок, договоры и подтверждения публикации образуют доказательственный набор. Серверное время и локальные хэши показывают согласованность версий, но владелец может выставить время сам. Хэш без независимой даты не доказывает дату создания.

Цифровая подпись связывает данные с ключом; установить владельца ключа и юридическое значение — отдельная задача. Подписанный архив лучше хранить вместе с подтверждением независимой даты (проверяемая служба timestamp или депонирование). Выбор сервиса зависит от юрисдикции и условий; автоматической гарантии признания нет. Непубличный ID помогает сопоставить версии, но не создаёт авторского права. Отпечатки, ранее созданные скриптом, не следует описывать как независимое депонирование.

## Проверки перед релизом

- View Source: нет полного скрытого платного текста, внутреннего JSON, ФИО в технических комментариях.
- DevTools Elements/Network: сравнить гостя, бесплатного и платного пользователя; отключить JS; проверить ответ напрямую без UI.
- Sources: нет закрытого корпуса и source maps; обязательные лицензии сохранены.
- Application: проверить localStorage, IndexedDB, Cache Storage, Service Worker; выход и смена аккаунта не показывают чужой отчёт.
- JS/CSS: поиск секретов/личных следов, визуальная проверка минификации, CSP и темы.
- API: отрицательные тесты прав, ограничения параметров, 429/Retry-After, отсутствие лишних полей и traceback. Нагрузку проверять только на тестовом окружении.
- HTTP: 200/401/403/404/422/429/500, публичный и персональный кэш, доверенные proxy headers.
- robots/sitemap: только выбранные страницы; noindex не считать приватностью.
- Метаданные: экспортные PDF/SVG/изображения; оригиналы не изменять.
- DNS: проверить известные записи и поддомены без массового сканирования; не менять MX/TXT без проверки назначения.
- Git/package/image: проверить отслеживаемые файлы, все опубликованные refs, архив пакета и слои образа, а не только .gitignore.

```powershell
curl.exe -I https://astrosmap.ru/
curl.exe -i https://astrosmap.ru/openapi.json
curl.exe -i https://astrosmap.ru/robots.txt
curl.exe -i https://astrosmap.ru/sitemap.xml
rg -n 'sourceMappingURL|@|author|copyright' frontend
git -C .source-publish-20260922 ls-files
Resolve-DnsName astrosmap.ru -Type MX
# Если инструменты установлены, читать только экспортные копии:
exiftool -a -G1 -s exported-image.jpg
pdfinfo exported-report.pdf
```

Команды — план, не утверждение об их выполнении. Не отправлять реальный Bearer-токен в отчёт или командную историю. Запросы /docs/OpenAPI безопасны как диагностика, но их отключение не заменяет защиту API.

## Порядок реализации и критерии готовности

1. Инвентаризация каждого источника контента (включая f-строки Python, JS, Kotlin, JSON, PDF-шаблоны и тестовые фикстуры), права и прежние публикации. Зафиксировать соответствие старых и новых ключей, оригиналы и контрольные ответы RU/EN.
2. Отделение редакционного пакета от логики без изменения формул. Не применять слепое извлечение всех строк: технические ключи, выражения и названия протокола должны сохраниться.
3. Сайт/PDF: сравнить результаты до/после, отсутствие потерь и перемешивания языков; API-проверка прав и поля brief/detailed. APK: согласовать офлайн-поведение, проверить сборку, тексты и кэш.
4. Лимиты сначала в наблюдении, затем постепенно; проверка нормальных сценариев, общих IP, мобильного приложения и поисковых роботов.
5. Экспорт сборки и метаданные: проверить отсутствие контента/секретов в исходном пакете, комплектность и лицензии. Исправление истории — только после полного перечня удаляемого, с резервной копией; старые копии и кеши не исчезают гарантированно.
6. Отдельная проверка production после разрешённой публикации. Не объявлять задачу завершённой по одному успешному тесту или удалению папки.
