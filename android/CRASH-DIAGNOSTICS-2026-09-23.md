# Диагностика вылетов — локальные изменения

## Поведение

В кабинете добавлен выключенный по умолчанию переключатель согласия. Только после включения необработанное JVM-исключение сохраняется в один ограниченный файл в noBackupFilesDir. При следующем запуске выполняется одна попытка отправки через существующий новый POST /api/mobile/reports. При отсутствии сети запись остаётся; повтор использует тот же UUID. После подтверждения сервером запись удаляется. Старые записи (более 7 дней) удаляются при следующем запуске с включённой диагностикой. Отключение удаляет ожидающую запись; уже начатую передачу нельзя отозвать.

Состав: тип исключения, максимум 10 кадров (имена классов/методов, номера строк), версия/код приложения, канал и Android API. Сообщение Throwable, cause, suppressed, имена файлов, потоков, пользовательские идентификаторы, карты, скриншоты не прикладываются. Максимум 1900 символов технического описания. Файлы не попадают в Android backup. Автоматические записи используют описание с префиксом Unhandled JVM exception; отдельного поля kind пока нет.

Перехват не подавляет исходный сбой: штатный uncaught handler вызывается в finally. В обработчике нет сетевого запроса. Ошибки самой диагностики не заменяют исходное исключение.

## Ограничения и проверка перед выпуском

- Это не сбор ANR, native crashes, принудительных завершений системой и ошибок до установки обработчика.
- При нехватке памяти/места запись может не сохраниться. Доставку каждого сбоя гарантировать нельзя.
- Пока нет инструментального теста на устройстве: проверить согласие off/on, намеренный тестовый сбой только в debug, перезапуск офлайн/онлайн, повтор без дубля, отключение и удаление ожидающей записи.
- Для release-стектрейсов сохранить соответствующий mapping.txt R8 каждого versionCode в закрытых артефактах сборки. Полезность обфусцированных кадров без mapping ограничена.
- Проверить сведения о диагностике в политике конфиденциальности и карточках магазинов до включения функции в выпуск.
- Новый серверный endpoint ещё не опубликован. Нужен отдельно разрешённый деплой; один процесс сервера — ограничение текущего хранилища.
- APK по-прежнему не выпускать до удаления встроенного авторского контента.

## Изменённые файлы этапа

- AstroApp.kt — установка обработчика при старте.
- data/CrashDiagnostics.kt — согласие, ограниченная запись и отправка при запуске.
- data/CrashSummary.kt — безопасное техническое описание.
- data/PendingCrashStore.kt — отдельно тестируемое хранение согласия и одного ожидающего отчёта.
- ui/account/FeedbackButton.kt — переключатель и объяснение.
- res/values/crash_diagnostics.xml и values-en/crash_diagnostics.xml.
- test/.../data/CrashSummaryTest.kt — проверки приватности и ограничения размера.
- test/.../data/PendingCrashStoreTest.kt — согласие по умолчанию, сохранение/отзыв согласия, удаление, повтор, подтверждение старого ID, срок хранения и повреждённые файлы.

Проверка 24 сентября: старые XML подтвердили 31 тест без failures/errors после добавления перехвата. Затем хранение выделено в отдельный класс, добавлены ещё 5 тестов; результат нового запуска фиксируется отдельно. Теперь отрицательное согласие записывается до удаления отчёта, результат удаления проверяется; повреждённые файлы удаляются, а не перечитываются при каждом старте.

Контракт API в этом этапе не менялся, используется API прошлого этапа. Коммит, push, деплой, выпуск не выполнялись. При распространении нужно обновить соответствующий публичный исходный код без закрытых данных.
