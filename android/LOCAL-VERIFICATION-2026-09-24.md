# AstroSMap — локальная проверка 24 сентября 2026

## Статус

Локальная проверка завершена в описанном ниже объёме. Воспроизведён локальный вылет standardDebug, исправлена гонка AstroEngine, пересобраны и проверены Google Play AAB и standard release APK. Эти файлы не готовы к загрузке в магазины: versionCode 11 уже использован, новые API ещё не развёрнуты, внешние действия требуют отдельного разрешения.

## Реализовано

- Регистрация отправляет все пять обязательных полей согласия и показывает понятные ошибки валидации.
- «Сферы жизни» показывают конкретные события highlights вместо повторяющегося общего текста.
- Ручные обращения с отдельным согласием, UUID для повтора, ограничением размера и защищённым просмотром в админке.
- Добровольная JVM-диагностика выключена по умолчанию; один ограниченный pending-файл вне backup, отправка при следующем запуске, срок 7 дней. Сообщение исключения и пользовательские данные не прикладываются.
- Авторские тексты Таро и лунных советов получаются с API в память процесса; генератор встроенного AndroidEditorial удалён.

## API и порядок выпуска

Добавлены POST /api/mobile/reports, GET /api/admin/mobile-reports и GET /api/mobile/editorial/v1. Основная схема БД не менялась. Нужен отдельно разрешённый серверный релиз до распространения клиента: закрытый пакет data/editorial/android-v1.json должен находиться на сервере. Endpoint ещё не деплоился.

ReportStore использует threading.Lock и один JSON-файл: безопасная эксплуатация требует одного процесса. Локальный run.py запускает один процесс, число production workers не проверено. До production подтвердить конфигурацию либо заменить хранение/синхронизацию. Лимит запросов также внутрипроцессный. Настройку reverse proxy и реального IP проверить при деплое.

## Ограничения выпуска

Версия 1.7.3 / code 11 уже использована по переданному контексту; повторная загрузка не подготовлена. Следующий code не назначался. Коммит, push, деплой и публикация не разрешены и не выполнялись.

LICENSE в дереве — AGPLv3. До распространения потребуется обновить соответствующий публичный исходный код и проверить полноту экспорта, сохранив исключение закрытых текстов, данных и ключей. Экспортёр сам не удостоверяет полноту или готовность к публикации. Актуальность remote-репозиториев здесь не проверялась. Локальный HEAD при проверке: e145ff2; это отличается от передачи, историю не меняли.

Проверить описание диагностики и обращений в политике конфиденциальности и сведениях магазинов о сборе данных. Прямые ссылки покупки закрыты SHOW_EXTERNAL_PURCHASE_LINKS=false в Google Play. Ссылка на живого таролога в Telegram в TarotScreen остаётся доступной; её назначение и дальнейший путь требуют отдельной проверки перед выпуском.

## Границы проверки контента

Сканер проверяет 352 известных длинных строки приватного пакета и старый descriptor AndroidEditorial в ZIP-записях. Ноль совпадений не доказывает отсутствие любых коротких, преобразованных или иных авторских текстов. Схема assets/db/cities.db содержит только таблицу географических данных cities; полный смысловой аудит каждой строки БД не выполнялся. Старые APK, пользовательские сохранения и уже показанные уведомления не удалены. При потере сети текст в памяти очищается после неуспешного refresh, а не мгновенно.

Текущий приватный пакет успешно прошёл load_package; ID фаз и знаков отдельно совпали с ключами клиента. Автоматический валидатор проверяет уникальность этих ID, но не полный ожидаемый набор: эту проверку нужно сохранять в процедуре обновления пакета.

## Найденный вылет и исправление

24 сентября при первом запуске свежего standardDebug журнал зафиксировал NoSuchElementException: Key Moon is missing in the map, AstroEngine.natal → TodayViewModel.moonOnly. До исправления параллельный тест одного экземпляра AstroEngine (4 потока, 80 расчётов) падал из-за некорректного результата Луны; одиночный расчёт без планетных файлов проходил. Движок внедряется как singleton, SwissEph использует изменяемые внутренние буферы.

На natal и transit добавлен общий монитор экземпляра (@Synchronized), охватывающий полный расчёт. После исправления прошли 6 golden-тестов и 2 новых регрессионных теста. StandardDebug загрузил главный экран с корректно отображённым лунным расчётом. В журнале до намеренного QA-сбоя новых JVM-вылетов не было.

Это подтверждённое исправление гонки локального движка. Тождественность этого дефекта прежним пользовательским вылетам не доказана; все возможные причины вылетов не закрыты. «Иероглифы» отдельно не воспроизведены. Последовательное выполнение расчётов на одном экземпляре — осознанная цена защиты mutable-буферов.

## Сквозная проверка standardDebug на emulator-5554

- Установка с сохранением данных (install -r), запуск MainActivity. Основной release-пакет не трогали.
- Главный экран после исправления: лунные данные и серверные тексты видны; позднее при недоступном QA API — нейтральные заглушки. Это проверка недоступности API, не всей матрицы смены сети/языка/виджетов.
- Регистрация нового синтетического пользователя через UI с двумя галочками: успешный переход в кабинет. Данные только во временной QA-БД, отправка SMTP отключена. Первоначальная попытка UI-автоматизации была неуспешна из-за работы с клавиатурой; успешный повтор проверен по экрану кабинета.
- Ручное обращение: UI показал квитанцию aaaad17a-844c-4168-8b70-bd33129a59e6; в отдельном временном хранилище ровно одна запись, store=standard.
- Диагностика до включения: переключатель false. Включена через UI, файл согласия содержит yes.
- Один намеренный сбой через am crash только ru.astrosmap.app.debug: pending c0b7d874-b424-4ffc-8c07-b0b0bc7dbb57 содержит тип CrashedByAdbException и 10 кадров, без сообщения исключения. После холодного запуска этот UUID есть на QA-сервере ровно один раз, локальный pending удалён.
- После теста диагностика отключена через UI: checked=false, файл согласия no. Временный QA-сервер остановлен через его собственную exec-сессию.
- Полная проверка offline retry/repeated launch/отзыва при ожидающем отчёте на устройстве не выполнялась; соответствующие механизмы частично покрыты unit-тестами. ANR/native/system kills не охвачены этой диагностикой.
- Google Play UI не проверялся APK: пользователь запретил любые Google Play APK. Проверки этого канала — unit-тесты, конфигурация и AAB-аудит.
